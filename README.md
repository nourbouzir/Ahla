# AHLA — Local Guide Matching Platform

> Book a local, not a tour: tourists in Tunisia spend a few hours with verified local hosts, matched by language, interests, location and rating.

**Team:** Salma Gzara, Nour Bouzir
**Course:** CS 488 — AI-First Software Engineering
**Status:** 🚧 In development (Lab 6: environment set up, implementation not started)

---

## What it does

Tourists visiting Tunisia struggle to find a trustworthy local who speaks their language and shares their interests; locals (students, artisans, fishermen, retirees) have no simple way to offer a few hours of their city or craft. AHLA lets hosts apply, get verified by an admin (ID check + video call), publish experiences and availability, and lets tourists search, request and pay for a booking, and message the host with automatic translation. The AI-assisted part is host recommendation: results are ranked by a match score (language, interests, proximity, rating) and each one shows a human-readable "why this host" reason.

## Tech stack

PHP 8.3 + Laravel 12 (Blade, plain JavaScript, Leaflet/OpenStreetMap), MySQL 8, Composer + npm (Vite assets), PHPUnit. Payment gateway and translation API providers are still to be chosen. See [ADR 0002](docs/decisions/0002-use-laravel-modular-monolith.md). (Keep in sync with `AI_CONTEXT.md`.)

## Getting started

Prerequisites: Git, PHP 8.3 with the `pdo_mysql`, `mbstring`, `intl` and `gd` extensions, Composer 2, Node 20+, MySQL 8 (or Laravel Sail with Docker). On Windows run the shell scripts in **Git Bash**.

```bash
# 1. Clone and enter the repo
git clone <your-repo-url>
cd ahla

# 2. One-time setup (installs git hooks, etc.)
./scripts/setup.sh

# 3. Copy environment template and fill in values
cp .env.example .env

# 4. Install dependencies
composer install
npm install
php artisan key:generate

# 5. Create the database (name from DB_DATABASE in .env), then migrate
php artisan migrate

# 6. Run the app (and, in a second terminal, the queue worker)
php artisan serve
php artisan queue:work

# 7. Run the tests and the style check (same as CI; tests need no MySQL)
composer test
composer lint
```

> **Where we are:** the app is a Laravel 12 skeleton with nine empty feature modules under `app/Modules/` (see [docs/setup.md](docs/setup.md) for how modules work). Features are built issue by issue; see [docs/PROJECT_PLAN.md](docs/PROJECT_PLAN.md) once it is merged.
